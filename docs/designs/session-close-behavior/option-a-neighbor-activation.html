与 Chrome / VS Code 一致：关闭页签 → 激活左侧相邻页签（最左则激活新的首个）； 关闭最后一个页签 → 画布立即进入真实空状态，不再残留已关闭会话的幽灵内容。 页签数据来自真实关闭路径，零「最后打开会话」回退。

行为对照 SPEC

close(tab) 有剩余激活 index-1 的相邻页签（左侧优先），内容同步切换，无闪烁
close(最后一个)现状：画布继续渲染已关闭会话（截图反馈的 bug） → 方案 A：立刻渲染空状态，composer 替换为 CTA
空状态内容app mark + 「没有打开的会话」+ 新建会话（⌘N）/ 查看全部会话；不预填任何旧会话数据
心智模型浏览器页签：页签即画布，页签没了画布就空。用户学习成本为零
风险误关无后悔药（需配合「重新打开已关闭页签 ⇧⌘T」或看方案 C）；空状态对「关完想继续看内容」的用户多一步
