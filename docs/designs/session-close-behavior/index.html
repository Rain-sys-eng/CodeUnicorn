关闭会话页签后，画布该显示什么？

现状（mac / win 一致）：关闭页签后画布默认回退到「最后打开的会话」； 关闭最后一个页签时，画布继续渲染刚刚被关闭的会话内容（幽灵内容），体验差且违反「页签已死」的直觉。 下面三个方案稿都可交互——直接点页签上的 × 体验，选定后进入 OpenSpec。

!
「windows 上最新版关闭最后一个页签显示的还是最后一个关闭的页签内容」 —— 用户反馈截图 · 2026（mac 同样存在）
A

浏览器式相邻激活 + 真实空状态

新窗口打开 ↗

Chrome / VS Code 语义：关闭 → 激活左侧相邻页签；关完 → 立即渲染空状态（app mark + 新建会话 ⌘N / 查看全部）。 稿内带「当前行为 / 方案行为」开关，可直接对照幽灵内容问题。改动最小、心智成本最低。

B

常驻「开始」页：永远的安全落点

新窗口打开 ↗

页签栏最左固定不可关闭的「开始」页签；关闭任意会话 → 回到开始页，被关会话带「刚刚关闭」标记列在最近会话顶部，单击恢复。 把「关闭」重新定义为「收起来」，同时给空窗口一个有价值的首页。适合多会话并行用户。

C

软关闭 + 可撤销（⇧⌘T）

新窗口打开 ↗

关闭语义同 A，但每次关闭都可撤销：底部 toast「已关闭 · 撤销 ⇧⌘T」（6s）；关闭最后一个 → 「已关闭」占位卡明确说明关了谁、内容还在，主按钮一键重新打开。 消灭误关焦虑，toast 不抢焦点。

三案对照矩阵

维度A · 相邻激活B · 常驻开始页C · 软关闭 + 撤销
关后有剩余页签 左相邻激活（浏览器语义） 回到开始页（或混合：走相邻） 左相邻激活 + 撤销 toast
关掉最后一个 纯空状态：新建 CTA 开始页：最近会话 + 新建 「已关闭」占位卡：重新打开 CTA
误关恢复 无（需另配 ⇧⌘T） 最近会话单击恢复 ⇧⌘T / toast / 占位卡三处可恢复
幽灵内容 消除 消除（落点永远有归属） 消除（占位卡是状态说明而非内容）
实现成本 低：改激活策略 + 空态组件 中：新增开始页签类型 + 最近列表数据 中：A 的基础上加撤销栈 + toast/占位卡
典型先例 Chrome / VS Code / Safari Edge 工作区 / Zed recent / 浏览器新标签页 Chrome ⇧⌘T / macOS 关闭确认 / Linear toast undo
建议 推荐 A 为基底（修 bug 的最小正确集），叠加 C 的 ⇧⌘T 撤销栈作为第二步；B 的「开始」页可作为后续独立 feature（新窗口默认落点）再评估。

三稿均用真实页签数据结构模拟（最多 5 个页签、7 字截断、引擎图标），顶栏语义与 topbarSessionTabs.ts 对齐。 拍板后按仓库 OpenSpec workflow 立项，behavior 变更落 openspec/changes/。
